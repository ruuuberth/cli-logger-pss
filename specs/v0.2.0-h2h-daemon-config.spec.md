# Feature: v0.2.0 — H2H Reports, Daemon Mode, Config Export/Import

## Overview

v0.2.0 introduces three major capabilities for power PSS players:
1. **H2H Comparative Reports** — Deep player-vs-player analytics with win rates, trophy/loot trends, and battle history
2. **Daemon Mode** — Headless background capture for continuous overnight/24/7 operation
3. **Config Export/Import** — Team-standard configuration distribution with YAML/JSON formats and auto-apply with backup

Target users: Hardcore PSS players analyzing meta, tracking rivals, and sharing standardized setups.
Timeline: Flexible (1-2 months) for thorough implementation and testing.

---

## Functional Requirements

### H2H Comparative Reports

#### FR-H2H-001: Generate H2H Report
While a battle replay database exists with at least one player matchup, when the user selects "Generar Reporte H2H" from the main menu and chooses two players, the system shall generate a comparative report containing win rates, trophy deltas, loot trends, and recent battle history.

#### FR-H2H-002: Player Selection from Battle List
While the user is in the H2H report flow, when they choose "Seleccionar de lista", the system shall display all unique player pairs from captured battles with battle counts, allowing selection by index.

#### FR-H2H-003: Player Search by Name/ID
While the user is in the H2H report flow, when they choose "Buscar por nombre/ID", the system shall accept a player name or user_id and return matching player pairs with battle counts for selection.

#### FR-H2H-004: Excel Multi-Sheet Output
Where Excel format is selected, the system shall generate a workbook with three sheets: "Resumen" (win rates, avg trophies, loot), "Batallas" (detailed battle list), and "Tendencias" (time-series data for win rate/trophies/loot over time).

#### FR-H2H-005: JSON Export
Where JSON format is selected, the system shall generate a structured JSON file containing all H2H metrics, battle list, and trend arrays for external analysis tools.

#### FR-H2H-005: Date Range Filter
While generating an H2H report, when the user specifies optional date_from and date_to filters, the system shall include only battles within that date range in all metrics and battle lists.

#### FR-H2H-006: Outcome Filter
While generating an H2H report, when the user specifies an outcome filter (VICTORY/DEFEAT/DRAW), the system shall include only battles matching that outcome.

### Daemon Mode

#### FR-DAEMON-001: Start Daemon via CLI
When the user runs `pss-native --daemon start`, the system shall start background capture using ApiFlowRuntime, write a PID file to `~/.logger-pss/daemon.pid`, and detach from the terminal.

#### FR-DAEMON-002: Stop Daemon via CLI
When the user runs `pss-native --daemon stop`, the system shall read the PID file, send SIGTERM to the process, wait for graceful shutdown (flush pending events), and remove the PID file.

#### FR-DAEMON-003: Daemon Status via CLI
When the user runs `pss-native --daemon status`, the system shall display capture running state, events captured this session, last battle captured, uptime, and any capture errors.

#### FR-DAEMON-004: Graceful Shutdown on Signal
While the daemon is running, when it receives SIGTERM or SIGINT, the system shall stop capture, flush pending events to database, close resources, and exit with code 0.

#### FR-DAEMON-005: PID File Management
While starting the daemon, if a stale PID file exists (process not running), the system shall warn and overwrite. While stopping, if no PID file exists, the system shall report "daemon not running".

#### FR-DAEMON-006: Config-Driven Behavior
Where DAEMON_* environment variables are set, the daemon shall respect DAEMON_PID_DIR, DAEMON_LOG_FILE, and DAEMON_CAPTURE_CONFIG for customization.

### Config Export/Import

#### FR-CONFIG-001: Export Configuration
While in the Settings menu, when the user selects "Exportar configuración" and chooses YAML or JSON format, the system shall write all current settings (from Pydantic Settings) to the specified file path, excluding sensitive values (masked as `***`).

#### FR-CONFIG-002: Import Configuration with Backup
While in the Settings menu, when the user selects "Importar configuración" and provides a YAML/JSON file, the system shall validate the file structure, create a timestamped backup of the current `.env`, auto-apply the imported settings to `.env`, and report success with backup path.

#### FR-CONFIG-003: Import Validation
Where an import file is provided, before applying, the system shall validate that all keys are known settings, value types match (bool, int, list, string), and required fields are present. On validation failure, the system shall report specific errors and not modify `.env`.

#### FR-CONFIG-004: Team Config Template
When exporting, the system shall include comments/descriptions for each setting in YAML format to serve as a team configuration template.

## Non-Functional Requirements

### Performance
- H2H Report generation: < 5 seconds for 10,000 battles
- Daemon startup: < 3 seconds to begin capturing
- Config export/import: < 1 second for typical settings

### Security
- Config export: Mask sensitive values (PSS_CHECKSUM_KEY, passwords) as `***` in output
- Config import: Never write masked values back; preserve existing secrets
- Daemon PID file: Restrict permissions to user-only (0600)

### Reliability
- Daemon: Must flush pending events on SIGTERM/SIGINT before exit
- Daemon: Must handle capture restart on mitmproxy crash (existing ApiFlowRuntime logic)
- H2H Report: Must handle empty matchups gracefully (no battles between players)

### Usability
- All new CLI commands follow existing menu patterns (numbered items, clear prompts)
- H2H player selection shows battle counts for quick identification
- Config import shows diff preview before auto-apply

### Compatibility
- Windows: Daemon uses threading (no fork), PID file in `%USERPROFILE%\.logger-pss`
- Linux: Daemon supports systemd (optional, out of scope for v0.2.0)
- Python 3.11+ only (consistent with project)

Given no daemon is running

Then daemon starts in background
And PID file is created at `~/.logger-pss/daemon.pid`

Given daemon is running with PID 12345
When the user runs `pss-native --daemon stop`
Then SIGTERM is sent to PID 12345
And daemon flushes pending events

Given daemon is running and has captured 50 events

And exits with code 0
And no events are lost

Given PID file exists but process is dead

Given no daemon is running
When user runs `pss-native --daemon stop`
Then system shows "Daemon no está en ejecución"

## Error Handling

| Error Condition | Context | User Message | System Action |
|-----------------|---------|--------------|---------------|
| No battles between players | H2H selection | "No hay batallas entre estos jugadores" | Return to player selection |
| Invalid date format | H2H filter | "Formato de fecha inválido. Use YYYY-MM-DD" | Re-prompt for date |
| Daemon already running | `daemon start` | "Daemon ya está ejecutándose (PID: XXXX)" | Exit 1 |
| Daemon not running | `daemon stop/status` | "Daemon no está en ejecución" | Exit 1 |
| Stale PID file | `daemon start` | "PID file existe pero proceso no corriendo. Sobrescribiendo..." | Overwrite and start |
| SIGTERM during capture | Daemon runtime | (logged internally) | Flush pending, exit 0 |
| Config file not found | Config import | "Archivo no encontrado: <path>" | Return to menu |
| Invalid YAML/JSON syntax | Config import | "Error de sintaxis en archivo: <details>" | Return to menu |
| Unknown config key | Config import validation | "Clave desconocida: <key>. Claves válidas: <list>" | Abort import, no .env change |
| Type mismatch (e.g. string for int) | Config import validation | "<key> debe ser <tipo>. Valor recibido: <value>" | Abort import, no .env change |
| Permission denied writing .env | Config import | "Sin permisos para escribir .env. Ejecute como administrador." | Abort import |
| Disk full on export | Config export | "Espacio insuficiente en disco" | Abort export |
